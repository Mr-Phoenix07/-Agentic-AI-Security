    # Web Application & API Penetration Testing  [webapp]
    A phased, OWASP-WSTG-aligned methodology for assessing the security of web applications and their APIs on authorized engagements — from passive reconnaissance through input-validation, authentication/authorization, session, business-logic and API testing, each step paired with the detection and mitigation guidance a defender needs.
    
    ⚖️  Run only against applications you own or are explicitly authorized to assess. In AEGIS, active probing of a live web target is gated by the fail-closed authorization scope (aegis/core/authorization.py); passive steps reason over the declared attack-surface inventory.
    
    6 phases · 11 techniques
    
    1. Reconnaissance & Information Gathering  (recon)
       goal: Map the application surface, technologies, and entry points before any active test.
         - [WSTG-INFO-01] Passive surface & fingerprinting  (sev-hint=low)
             objective: Enumerate hosts, subdomains, technologies, and framework/version disclosure without touching sensitive functionality.
             frameworks: owasp_wstg:WSTG-INFO-02,WSTG-INFO-08; mitre_attack:T1595 Active Scanning,T1592 Gather Victim Host Information
         - [WSTG-CONF-01] Configuration & deployment review  (sev-hint=medium)
             objective: Identify insecure platform/config: default files, exposed admin, TLS posture, security headers, CORS.
             frameworks: owasp_wstg:WSTG-CONF-07,WSTG-CONF-08; owasp_top10:A05:2021 Security Misconfiguration; owasp_asvs:V14 Configuration
    
    2. Identity, Authentication & Session Management  (identity)
       goal: Verify that users are authenticated robustly and sessions cannot be hijacked or fixed.
         - [WSTG-ATHN-01] Authentication robustness  (sev-hint=high)
             objective: Assess resistance to credential stuffing, brute force, weak password policy, and username enumeration.
             frameworks: owasp_wstg:WSTG-ATHN-03,WSTG-IDNT-04; owasp_top10:A07:2021 Identification and Authentication Failures; mitre_attack:T1110 Brute Force,T1078 Valid Accounts
         - [WSTG-SESS-01] Session management  (sev-hint=high)
             objective: Verify session tokens are unpredictable, rotated on privilege change, invalidated on logout, and protected in transit.
             frameworks: owasp_wstg:WSTG-SESS-02,WSTG-SESS-03; owasp_top10:A07:2021; owasp_asvs:V3 Session Management
    
    3. Authorization  (authorization)
       goal: Confirm access controls enforce least privilege across objects and functions.
         - [WSTG-ATHZ-01] Broken object/function level authorization (BOLA/BFLA)  (sev-hint=critical)
             objective: Detect horizontal and vertical privilege escalation: accessing other users' objects or admin functions.
             frameworks: owasp_wstg:WSTG-ATHZ-04; owasp_api:API1:2023 BOLA,API5:2023 BFLA; owasp_top10:A01:2021 Broken Access Control
    
    4. Input Validation & Injection  (input)
       goal: Determine whether untrusted input can alter query, command, markup, or template semantics.
         - [WSTG-INPV-05] Injection (SQL/NoSQL/command/template)  (sev-hint=critical)
             objective: Assess whether user input crosses a code/data boundary in queries, OS commands, or template engines.
             frameworks: owasp_wstg:WSTG-INPV-05,WSTG-INPV-12; owasp_top10:A03:2021 Injection; mitre_attack:T1190 Exploit Public-Facing Application
         - [WSTG-INPV-01] Cross-site scripting (reflected/stored/DOM)  (sev-hint=high)
             objective: Assess whether input is rendered into a browser context without correct encoding, enabling script execution.
             frameworks: owasp_wstg:WSTG-INPV-01,WSTG-CLNT-01; owasp_top10:A03:2021 Injection
         - [WSTG-INPV-19] Server-side request forgery (SSRF)  (sev-hint=high)
             objective: Determine whether the server can be coerced into making attacker-controlled requests (e.g., to cloud metadata or internal services).
             frameworks: owasp_wstg:WSTG-INPV-19; owasp_top10:A10:2021 SSRF; mitre_attack:T1190
    
    5. Business Logic & API Security  (logic-api)
       goal: Test workflow integrity and API-specific weaknesses beyond generic injection.
         - [WSTG-BUSL-01] Business-logic & workflow abuse  (sev-hint=high)
             objective: Identify flows that can be replayed, reordered, or manipulated (price/quantity tampering, race conditions, insufficient limits).
             frameworks: owasp_wstg:WSTG-BUSL-01,WSTG-BUSL-07; owasp_api:API6:2023 Unrestricted Access to Sensitive Business Flows
         - [API-RL-01] Unrestricted resource consumption & rate limiting  (sev-hint=medium)
             objective: Determine whether expensive or state-changing endpoints (including AI/inference) enforce authentication and rate/quota limits.
             frameworks: owasp_api:API4:2023 Unrestricted Resource Consumption,API2:2023 Broken Authentication; owasp_top10:A04:2021 Insecure Design
    
    6. Analysis, Evidence & Reporting  (report)
       goal: Turn measured weaknesses into reproducible, standards-mapped findings with remediation.
         - [RPT-01] Evidence collection & standards mapping  (sev-hint=info)
             objective: Record reproducible evidence for each finding and map it to OWASP/ASVS/ATT&CK with severity and confidence.
             frameworks: ptes:Reporting; owasp_asvs:V1 Architecture, Design and Threat Modeling
    
    References: owasp_wstg (OWASP Web Security Testing Guide v4.2), owasp_top10 (OWASP Top 10:2021), owasp_api (OWASP API Security Top 10:2023), owasp_asvs (OWASP Application Security Verification Standard 4.0), mitre_attack (MITRE ATT&CK Enterprise), ptes (Penetration Testing Execution Standard)

    # Active Directory Security Assessment  [active-directory]
    An assumed-breach, ATT&CK-aligned methodology for assessing Active Directory: discovery and enumeration, credential-access exposure, lateral-movement paths, privilege-escalation and domain-dominance conditions, and persistence — each paired with the Windows detection telemetry and hardening control that closes it.
    
    ⚖️  Run only inside a directory you own or are explicitly authorized to assess (signed rules of engagement). Prefer a lab or an isolated, monitored assessment window; coordinate with the blue team so detections can be validated. In AEGIS, hosts/scopes are enforced fail-closed and active checks run only through the controlled-validation path.
    
    5 phases · 9 techniques
    
    1. Discovery & Enumeration  (discovery)
       goal: Build an accurate model of the domain: principals, groups, trusts, and privileged relationships.
         - [AD-DISC-01] Domain, user, and group enumeration  (sev-hint=low)
             objective: Inventory domain objects, group memberships, GPOs, and trusts to map the identity terrain (typically via authenticated LDAP as any domain user).
             frameworks: mitre_attack:T1087 Account Discovery,T1069 Permission Groups Discovery,T1482 Domain Trust Discovery
         - [AD-DISC-02] Attack-path / ACL relationship analysis  (sev-hint=high)
             objective: Identify dangerous ACLs and delegation (GenericAll, WriteDACL, GenericWrite, constrained/unconstrained delegation) that form escalation edges to Domain Admin.
             frameworks: mitre_attack:T1069,T1078.002 Domain Accounts
    
    2. Credential Access Exposure  (credential-access)
       goal: Determine whether credential material can be obtained from Kerberos, the directory, or endpoints.
         - [AD-CRED-01] Kerberoasting exposure (service-account SPNs)  (sev-hint=high)
             objective: Assess whether service accounts with SPNs use weak, crackable passwords, allowing offline recovery of service-ticket-encrypted credentials.
             frameworks: mitre_attack:T1558.003 Kerberoasting
         - [AD-CRED-02] AS-REP roasting exposure (pre-auth disabled)  (sev-hint=medium)
             objective: Identify accounts with Kerberos pre-authentication disabled, whose AS-REP can be recovered offline.
             frameworks: mitre_attack:T1558.004 AS-REP Roasting
         - [AD-CRED-03] Endpoint credential-material exposure  (sev-hint=high)
             objective: Assess exposure of cached credentials, tokens, and secrets on endpoints (LSASS memory, credential caches, SYSVOL scripts/GPP).
             frameworks: mitre_attack:T1003 OS Credential Dumping,T1552 Unsecured Credentials
    
    3. Lateral Movement  (lateral)
       goal: Evaluate whether obtained credentials/tickets enable movement between hosts.
         - [AD-LAT-01] Credential-reuse & ticket-based movement  (sev-hint=high)
             objective: Determine whether hash/ticket reuse (pass-the-hash / pass-the-ticket) or over-broad local-admin rights allow lateral movement.
             frameworks: mitre_attack:T1550.002 Pass the Hash,T1550.003 Pass the Ticket,T1021 Remote Services
    
    4. Privilege Escalation & Domain Dominance  (escalation)
       goal: Identify conditions that grant domain-wide control.
         - [AD-ESC-01] Directory-replication (DCSync) rights exposure  (sev-hint=critical)
             objective: Assess whether non-DC principals hold replication rights (Replicating Directory Changes / All) enabling secret extraction of any account.
             frameworks: mitre_attack:T1003.006 DCSync
         - [AD-ESC-02] AD Certificate Services (AD CS) misconfiguration  (sev-hint=critical)
             objective: Identify vulnerable certificate templates / CA settings that permit authentication-capable certificate issuance for arbitrary principals.
             frameworks: mitre_attack:T1649 Steal or Forge Authentication Certificates
    
    5. Persistence & Defense Validation  (persistence)
       goal: Assess durable-access conditions and validate that detections/hardening are effective.
         - [AD-PERS-01] Persistence-condition & Tier-0 integrity review  (sev-hint=high)
             objective: Identify conditions enabling durable domain access (e.g., forged-ticket exposure via krbtgt hygiene, rogue trusts, GPO abuse) and verify Tier-0 isolation.
             frameworks: mitre_attack:T1558.001 Golden Ticket,T1484.002 Domain Trust Modification,T1484.001 Group Policy Modification
    
    References: mitre_attack (MITRE ATT&CK Enterprise (Windows / Active Directory)), ms_hardening (Microsoft Securing Active Directory / Tiered Admin model), cisa (CISA AD Security guidance), nist_800_53 (NIST SP 800-53 access-control & audit families)

    # AI / LLM / Agentic Red-Teaming  [ai-redteam]
    A phased methodology for adversarial evaluation of AI systems — LLMs, RAG pipelines, and agentic/MCP surfaces — spanning threat modeling, attack-surface mapping, adversarial execution (prompt injection, jailbreak, tool/agent abuse, RAG poisoning, multimodal), evidence-based scoring, and remediation. It is the human-readable companion to AEGIS's adaptive evaluation loop and 23-agent collective.
    
    ⚖️  Assess only AI systems you own or are explicitly authorized to evaluate. AEGIS routes every provider request through the fail-closed authorization scope; the mutation framework produces semantics-preserving re-encodings to measure robustness and calibration, not to defeat safety controls.
    
    5 phases · 8 techniques
    
    1. Planning & Threat Modeling  (plan)
       goal: Define scope, objectives, risk profile, and rules of engagement before probing.
         - [AIRT-PLAN-01] Threat modeling & scoping  (sev-hint=info)
             objective: Enumerate assets, trust boundaries, and abuse cases for the AI system; set measurable objectives and an authorized scope.
             frameworks: nist_ai_rmf:GOVERN 1,MAP 1,MAP 5; guide:Phase 1: Planning & Threat Modeling
    
    2. Reconnaissance & Attack-Surface Mapping  (map)
       goal: Discover and characterise the AI surface: models, RAG stores, tools, agents, and exposed endpoints.
         - [AIRT-MAP-01] AI attack-surface detection  (sev-hint=medium)
             objective: Identify inference endpoints, RAG retrieval, MCP tools/resources, and agent autonomy, and flag those that are unauthenticated or unbounded.
             frameworks: owasp_llm:LLM06:2025 Excessive Agency; owasp_agentic:ASI02 Tool Misuse,ASI05 Privilege Compromise; redamon:Recon: AI Surface detection
    
    3. Adversarial Execution  (execute)
       goal: Probe model, RAG, and agent behaviour with reproducible, semantics-preserving adversarial inputs.
         - [AIRT-EXE-01] Prompt injection & instruction-hierarchy testing  (sev-hint=high)
             objective: Measure susceptibility to direct and indirect prompt injection and to instruction-hierarchy override (system vs. user vs. tool content).
             frameworks: owasp_llm:LLM01:2025 Prompt Injection; mitre_atlas:AML.T0051 LLM Prompt Injection,AML.T0054 LLM Jailbreak; owasp_agentic:ASI01 Agent Instruction Manipulation
         - [AIRT-EXE-02] Agentic / tool-abuse & excessive-agency testing  (sev-hint=high)
             objective: Determine whether an agent can be steered to misuse tools, exceed authority, or chain actions toward a harmful goal.
             frameworks: owasp_llm:LLM06:2025 Excessive Agency; owasp_agentic:ASI02 Tool Misuse,ASI03 Goal Manipulation,ASI05 Privilege Compromise; mitre_atlas:AML.T0053 LLM Plugin Compromise
         - [AIRT-EXE-03] RAG grounding & poisoning testing  (sev-hint=medium)
             objective: Assess grounding rate, unsupported-citation behaviour, and susceptibility to retrieval/context poisoning.
             frameworks: owasp_llm:LLM08:2025 Vector & Embedding Weaknesses,LLM09:2025 Misinformation; mitre_atlas:AML.T0070 RAG Poisoning
         - [AIRT-EXE-04] Robustness, calibration & sensitive-data-exposure testing  (sev-hint=medium)
             objective: Measure output stability under benign re-encoding, confidence calibration, and resistance to training/system-data disclosure.
             frameworks: owasp_llm:LLM02:2025 Sensitive Information Disclosure,LLM09:2025 Misinformation; mitre_atlas:AML.T0043 Craft Adversarial Data; nist_ai_rmf:MEASURE 2.5,MEASURE 2.9
    
    4. Evaluation & Scoring  (score)
       goal: Quantify results with reproducible, statistically grounded metrics.
         - [AIRT-SCORE-01] Attack-success-rate & confidence scoring  (sev-hint=info)
             objective: Compute per-dimension success/failure rates with calibrated confidence and derive severity from measured shortfall × confidence.
             frameworks: nist_ai_rmf:MEASURE 2.3,MEASURE 2.7; guide:Phase 3: Evaluation & Scoring
    
    5. Reporting & Remediation  (remediate)
       goal: Deliver standards-mapped findings, mitigations, and regression tests, then re-test.
         - [AIRT-REM-01] Remediation, regression & continuous validation  (sev-hint=info)
             objective: Attach mitigation guidance and a regression test to each finding, and re-run to confirm closure and prevent regression.
             frameworks: nist_ai_rmf:MANAGE 4.1; guide:Phase 4: Reporting & Remediation; redamon:Triage & Remediation
    
    References: owasp_llm (OWASP Top 10 for LLM Applications 2025), owasp_agentic (OWASP Top 10 for Agentic Applications (ASI01–ASI10)), mitre_atlas (MITRE ATLAS), nist_ai_rmf (NIST AI Risk Management Framework 1.0), guide (AI Red-Teaming Guide (requie/AI-Red-Teaming-Guide)), redamon (redamon autonomous pipeline (samugit83/redamon) — pipeline shape only)
